# CatHat 工作约定

## 会话角色

- 主控负责判断、分工和验收。带 `【子任务】` 的消息是明确的子任务说明，只做任务边界内的工作。主控通过父子关系管理子线程，不跨线程接管其它主控的工作。
- 主控对复杂问题最多做三次探查，每次先写清需要验证的事实。三次后仍需要深入排查，就开子线程并交接证据。发现已有同目标的子线程时优先用 `bb thread tell` 续派。每个主控最多同时运行三个子线程。
- 派活前读本工作区的 CatHat Dispatch skill。默认用 `stuck`，只有主控确实要接力时才用 `auto`，并在任务说明写出接力动作。
- 子线程进入等待时保持安静。若主控或用户已托管，持续处理授权范围内可恢复的卡点，完成后给出结果和证据。交接时只写需要接手的动作。主动上报真实阻塞、范围变化或需要用户拍板的决定。

## 验证和巡检

先核对一手证据，区分事实、推断和未知。汇报第一段写结论、失败及验证边界，附原产物位置。无权限或缺关键输入时直接说明卡点。涉及发布、生产变更或不可逆操作时，以用户授权为准。

等待外部流程时，可在 BB 的 Automations 建一条单次闹钟：写清复查时间、要查的任务 ID、证据与完成条件。触发时只查一次并更新结论；确实需要下一次才重新设置。

## 记忆

用 `bb memory status` 看当前索引。通用偏好记入 `memory/global/`；本项目的经验记入 `memory/projects/cathat/`。索引链接到简短笔记，保留出处与日期。Dreaming 启用后会定期整理可复用事实。
